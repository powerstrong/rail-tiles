# Rail Tiles

격자 위에 레일을 놓아 작은 기차를 출발역에서 도착역까지 데려다주는 싱글플레이 퍼즐 웹게임입니다.
백엔드 없이 브라우저만으로 실행됩니다.

현재 상태: **v0.2. 스테이지 14개, 별 도전, 힌트, 터널**  
플레이: https://powerstrong.github.io/rail-tiles/

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # Vitest 단위 테스트
npm run build      # 타입 검사 + 프로덕션 빌드 (dist/)
npm run stages     # 스테이지별 정답 경로 수, 최소 레일 수, 정답 그림 출력
```

### 배포

**GitHub Pages:** https://powerstrong.github.io/rail-tiles/

`main`에 푸시하면 `.github/workflows/deploy.yml`이 테스트, 빌드, 배포를 자동으로 실행합니다.
빌드는 상대 경로(`base: './'`)를 쓰므로 다른 정적 호스팅(Cloudflare Pages 등)에도
빌드 명령 `npm run build`, 출력 디렉터리 `dist`로 그대로 올릴 수 있습니다.

## 조작

| 동작 | PC | 모바일 |
|---|---|---|
| 레일 놓기 | 도구 선택 후 빈칸 클릭 | 도구 선택 후 빈칸 탭 |
| 회전 | 놓인 레일 클릭 | 놓인 레일 탭 |
| 종류 바꾸기 | 다른 레일 도구로 놓인 레일 클릭 | 다른 레일 도구로 놓인 레일 탭 |
| 지우기 | 지우개 도구로 클릭 | 지우개 도구로 탭 |
| 도구 전환 | `1` `2` `3` / `E` | 하단 도구 버튼 |
| 되돌리기 | `Ctrl+Z` 또는 ↶ | ↶ 버튼 |
| 출발 | `Enter` 또는 출발 버튼 | 출발 버튼 |

새 레일은 이웃한 레일과 역을 보고 연결되는 방향으로 자동으로 놓입니다.
직선이 놓인 칸을 곡선 도구로 누르면 직선은 회수되고 곡선으로 바뀝니다(반대도 같음). 실패해도 배치는 그대로 남습니다.
헤더의 스피커 버튼으로 효과음을 끄고 켤 수 있습니다(설정은 저장됨).

### 별과 힌트

- 스테이지마다 **par**(이길 수 있는 최소 레일 수)가 있습니다. par 이하로 클리어하면 ★★★, par+2 이하면 ★★, 그 외는 ★입니다.
- 클리어에는 여유 레일이 주어지므로, 클리어 자체보다 ★★★가 진짜 도전입니다.
- **힌트** 버튼은 정답 레일 한 칸을 보여 줍니다. 힌트를 쓰면 이번 클리어는 최대 ★★입니다.
- 가장 좋은 기록이 저장됩니다(진행 데이터 v2. 예전 v1 기록은 클리어당 ★1로 자동 이전).

## 구조

```
src/
  engine/            순수 TypeScript 게임 엔진 (React/DOM 의존 없음)
    dir.ts           방향(N/E/S/W)과 좌표 보조 함수
    rail.ts          레일 종류, 회전, 포트(연결 변) 표
    stage.ts         스테이지 형식(ASCII 맵) 파싱과 검증
    simulate.ts      기차 주행 계산: 경로 trace와 실패 원인/위치
    editor.ts        배치·회전·삭제·undo·초기화, 자동 방향 맞춤
    solver.ts        DFS 솔버: 해의 개수, 최소 레일 수
    geometry.ts      궤도 기하. 레일 그림과 기차 이동이 같은 중심선을 공유
  stages/stages.ts   손으로 만든 스테이지 (ASCII 맵 + 정답)
  ui/                React 화면과 SVG 아트
    art/             팔레트, 레일, 지형, 역, 기차 SVG 컴포넌트
    Board.tsx        게임판 렌더링과 입력
    GameScreen.tsx   편집 → 주행 → 결과 상태 흐름
    trainRunner.ts   requestAnimationFrame 기반 기차 주행 (React 재렌더 없음)
    sound.ts         Web Audio로 합성한 효과음 (에셋 파일 없음)
  storage.ts         localStorage 진행 기록 (손상된 데이터는 초기화)
scripts/

  stage-design.ts    npm run stage-design -- drafts.ts: 초안 맵의 인벤토리별 경로 수 표
```

### 핵심 설계

- **결과를 먼저 계산하고 재생:** `simulate()`가 기차 경로 전체와 실패 원인·위치를 계산하고,
  UI는 그 trace를 애니메이션으로 보여 주기만 합니다.
- **같은 기하 공유:** `geometry.ts`의 선분과 원호가 레일 SVG와 기차 위치 계산에 모두 쓰입니다.
  그래서 기차가 곡선에서도 레일 중심을 정확히 따라갑니다.
- **루프 불가:** 모든 조각은 연결 변이 정확히 두 개이고 출발역은 한쪽 끝점이므로,
  기차가 순환 경로에 빠질 수 없습니다. 최대 스텝 제한은 분기기를 넣을 때를 대비한 안전장치입니다.
- **스테이지 난이도 고정:** `stages.test.ts`가 스테이지마다 솔버의 해 개수를 고정해 둡니다.
  스테이지를 고쳐서 지름길이 생기면 테스트가 실패합니다.

## 스테이지 만들기

`src/stages/stages.ts`에 `StageDef`를 추가합니다. 맵 기호:

```
.  빈칸          P  승객(경유지)    S  출발역    G  도착역
T  나무   R  바위   M  산   W  물   H  집
│ ─ └ ┌ ┐ ┘   고정 레일
a b c …       터널 입구 (같은 글자 두 개가 한 쌍)
```

터널은 `tunnels: { a: ['E', 'W'] }`처럼 읽는 순서(위→아래, 왼→오)로 첫 번째·두 번째 입구가
열린 방향을 적습니다.

`║ ═`는 강 위의 고정 다리입니다. `solution`에는 같은 크기의 격자에 **최단** 정답 레일을 적고(레일 수가 par가 됨),
`stages.test.ts`의 `EXPECTED_ROUTES`에 해 개수를 기록합니다.

새 스테이지 설계 순서:

1. 초안 맵을 `StageDef` 배열로 export하는 파일을 만듭니다(인벤토리와 solution은 임시값).
2. `npm run stage-design -- 초안.ts`로 직선×곡선 수량별 경로 수 표를 봅니다.
3. 경로가 1~3개이고, 눈에 띄는 지름길이 수량 때문에 막히는 인벤토리를 고릅니다.
4. 출력된 `solution:` 줄을 복사해 `stages.ts`에 넣고 `EXPECTED_ROUTES`를 기록합니다.
