# Rail Tiles

격자 위에 레일을 놓아 작은 기차를 출발역에서 도착역까지 데려다주는 싱글플레이 퍼즐 웹게임입니다.
백엔드 없이 브라우저만으로 실행됩니다.

현재 상태: **v0.7. 월드 2개 · 스테이지 70개.** 기차 월드(40판: 터널, 교차로, 분기기, 손님 배달, 오늘의 퍼즐)와
펭귄 얼음 나라(30판: 미끄럼 퍼즐). 별 도전, 힌트, 드래그 배치  
플레이: https://powerstrong.github.io/rail-tiles/

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # Vitest 단위 테스트
npm run build      # 타입 검사 + 프로덕션 빌드 (dist/)
npm run stages     # 스테이지별 정답 경로 수, 최소 레일 수, 정답 그림 출력
npm run difficulty # 스테이지별 난이도 점수(배포 전 확인용)
```

### 배포

**GitHub Pages:** https://powerstrong.github.io/rail-tiles/

`main`에 푸시하면 `.github/workflows/deploy.yml`이 테스트, 빌드, 배포를 자동으로 실행합니다.
빌드는 상대 경로(`base: './'`)를 쓰므로 다른 정적 호스팅(Cloudflare Pages 등)에도
빌드 명령 `npm run build`, 출력 디렉터리 `dist`로 그대로 올릴 수 있습니다.

## 조작

| 동작 | PC | 모바일 |
|---|---|---|
| 레일 놓기 | 도구 선택 후 빈칸 클릭 | 도구 선택 후 빈칸 탭 |
| 여러 칸 한 번에 놓기 | 누른 채로 드래그 | 꾹 누른 채로 드래그 |
| 회전 | 놓인 레일 클릭 | 놓인 레일 탭 |
| 종류 바꾸기 | 다른 레일 도구로 놓인 레일 클릭 | 다른 레일 도구로 놓인 레일 탭 |
| 지우기 | 지우개 도구로 클릭(드래그로 여러 칸) | 지우개 도구로 탭(드래그로 여러 칸) |
| 도구 전환 | `1`~`4` / `E` | 하단 도구 버튼 |
| 되돌리기 | `Ctrl+Z` 또는 ↶ | ↶ 버튼 |
| 출발 | `Enter` 또는 출발 버튼 | 출발 버튼 |

새 레일은 이웃한 레일과 역을 보고 연결되는 방향으로 자동으로 놓입니다.
드래그로 놓으면 끌고 간 순서대로 서로 이어지게 놓이고(빈칸만 채움), 드래그 한 번은 되돌리기 한 번으로 취소됩니다.
기차는 손님 칸에서 잠깐 멈추고, 손님이 인사한 뒤 올라탑니다.
직선이 놓인 칸을 곡선 도구로 누르면 직선은 회수되고 곡선으로 바뀝니다(반대도 같음). 실패해도 배치는 그대로 남습니다.
헤더의 스피커 버튼으로 효과음을 끄고 켤 수 있습니다(설정은 저장됨).
클리어 화면에서는 다음 스테이지, **배치 고치기**(놓은 레일 유지), **처음부터 다시**(빈 판, 힌트 제한 해제),
오른쪽 위 X 버튼(스테이지 목록으로)을 고를 수 있습니다.

### 오늘의 퍼즐

- 6스테이지(첫 손님)를 깨면 스테이지 목록 맨 위에 **오늘의 퍼즐**이 열립니다. 날짜마다 새 맵이 나오고,
  같은 날에는 모든 기기에서 같은 퍼즐입니다(날짜를 시드로 쓰는 결정적 생성).
- 생성기(`src/engine/generate.ts`)가 무작위 맵(6×6 또는 7×7, 장애물 덩어리, 손님 0~2명)을 그리고,
  솔버로 모든 정답 경로를 센 뒤 퍼즐다운 맵만 고릅니다: ★★★ 정답 1~2개, ★★/★ 경로 2개 이상,
  최단 경로가 판 크기보다 길고 곡선 4개 이상. 레일 수량은 최단 경로가 쓰는 만큼 + 약간의 여유입니다.
- 생성은 Web Worker에서 돌아 화면이 멈추지 않고, 결과는 그날 하루 기기에 캐시됩니다.
- 매일 클리어하면 **연속 기록(🔥 N일 연속)**이 쌓입니다.
- `npx vite-node scripts/daily-report.ts 2026-10-19 30`으로 날짜별 생성 시간, par, 별 분포를 점검합니다.

### 별과 힌트

- 스테이지마다 **par**(이길 수 있는 최소 레일 수)가 있습니다. par 이하로 클리어하면 ★★★, par+2 이하면 ★★, 그 외는 ★입니다.
- 레일은 넉넉히 주어집니다. 돌아가는 길로도 클리어할 수 있지만 그러면 ★★나 ★가 되고, ★★★는 최단 경로를 찾아야 합니다.
- 튜토리얼(1, 11)을 제외한 모든 스테이지에서 ★★★가 아닌 클리어가 가능한지 테스트로 보장합니다.
- **힌트** 버튼은 정답 레일 한 칸을 보여 줍니다. 힌트를 쓰면 이번 클리어는 최대 ★★입니다.
  주행에 실패한 뒤 누르면 기차를 출발역으로 되돌리고 힌트를 보여 줍니다.
  클리어 화면의 **처음부터 다시**나 스테이지 재입장으로 힌트 제한이 풀립니다.
- 가장 좋은 기록이 저장됩니다(진행 데이터 v2. 예전 v1 기록은 클리어당 ★1로 자동 이전).

## 월드

타이틀 다음은 **월드 선택** 화면입니다. 월드마다 퍼즐 종류와 테마가 다르고, 앞 월드의 마지막 보스를 깨면
다음 월드가 열립니다. 기계 월드, 화산 월드는 "곧 열려요" 카드로 예고되어 있습니다.

| 월드 | 퍼즐 | 챕터 |
|---|---|---|
| 1 기차 월드 | 레일을 깔아 기차를 도착역까지 | 기본 선로 · 산과 터널 · 교차로와 분기기 · 손님 배달 (4×10판) |
| 2 펭귄 얼음 나라 | 펭귄을 밀면 부딪힐 때까지 미끄러짐. 자기 색 낚시 구멍에 딱 멈추면 성공 | 얼음 미끄럼 · 이글루와 친구들 · 바다와 해류 (3×10판) |

### 펭귄 얼음 나라 규칙

- 펭귄을 손가락으로 쓱 밀거나(스와이프), 화면 아래 화살표를 누르거나, 펭귄과 같은 줄의 칸을 누르면 그쪽으로 밉니다.
  펭귄이 여럿이면 펭귄을 눌러 고릅니다. PC는 방향키, `1`~`3`으로 펭귄 선택, `Ctrl+Z` 되돌리기.
- 바위·눈사람·판 끝·다른 펭귄에 부딪히면 그 앞에서 멈춥니다. 모든 펭귄이 자기 색 구멍에 동시에 멈춰 있고
  물고기를 모두 먹으면 성공입니다(구멍 위를 미끄러져 지나가기만 하면 안 됨).
- **눈더미:** 올라서면 푹 빠져 그 자리에 멈춤. **물고기:** 지나가거나 멈추면 먹음.
- **바다:** 미끄러져 들어가면 풍덩(그 밀기는 취소되고 펭귄이 제자리로 돌아옴).
- **이글루:** 문으로 들어가면 같은 번호 이글루의 문으로 튀어나와 그 방향으로 계속 미끄러짐. 다른 면은 벽.
- **해류:** 지나가면 화살표 방향으로 꺾임. **금 간 얼음:** 펭귄이 한 번 떠나면 깨져서 바다가 됨.
- 별: 최소 밀기 횟수(par) 이하 ★★★, par+2 이하 ★★, 그 외 ★. 힌트는 지금 상태에서 가장 빠른 다음 한 수를 화살표로 보여 줍니다.
- 엔진은 `src/penguin/`: `slide.ts`(규칙 하나로 화면과 솔버가 공유), `solver.ts`(상태 전체 너비 우선 탐색, 최소 횟수·정답 수·힌트),
  `audit.ts`(난이도), `stages.ts`(30판). 모든 판은 테스트가 정답·최소 횟수·★★★ 정답이 하나뿐임을 확인합니다.
- 판 만들기: `npx vite-node scripts/ice-search.ts 사양.ts`. 크기, 펭귄 수, 기믹 개수, 밀기 횟수와 난이도 범위,
  정답에서 꼭 써야 하는 기믹(`must`)을 적으면 무작위 판을 풀어 보고 조건에 맞는 판을 골라 줍니다.
- 난이도 점수(`npm run difficulty` 아래쪽): 밀기 횟수 × 1.5 + log2(갈 수 있는 상태 수) × 2 + 막다른 길이 있는 단계 × 2
  + 돌아가는 수 × 0.3. 챕터 첫 판이 앞 챕터 첫 판보다, 보스가 앞 보스보다 높도록 놓았습니다
  (첫 판 10 → 17 → 19, 보스 42 → 59 → 67).

## 스테이지

챕터 4개, 챕터마다 10판씩 모두 40판입니다. 판 번호는 `챕터-순서`(예: 2-5)로 표시합니다.
각 챕터는 쉬운 연습판으로 시작해 점점 어려워지고, 마지막 판이 그 챕터의 보스 판입니다.
앞 판을 깨면(별 1개 이상) 다음 판이 열립니다. 이미 깬 판은 항상 열려 있어서,
나중에 챕터 중간에 판이 추가되어도 예전 기록 때문에 막히지 않습니다.

| 판 | 챕터 1 · 기본 선로 | 챕터 2 · 산과 터널 | 챕터 3 · 교차로와 분기기 | 챕터 4 · 손님 배달 |
|---|---|---|---|---|
| 1 | 첫 번째 선로 (2) | 터널 통과 (10) | 교차로 (20) | 첫 배달 ★ (13) |
| 2 | 모퉁이 돌기 (9) | 강 밑 터널 ★ (14) | 한 바퀴 돌아 교차 ★ (18) | 분기기 배달 ★ (14) |
| 3 | 언덕 너머 (10) | 돌아서 들어가기 (14) | 선로 전환기 (13) | 터널 택배 ★ (15) |
| 4 | 강 건너기 (13) | 터널 너머 손님 ★ (14) | 반대로 놓인 분기기 (10) | 먼저 태우고 내려요 ★ (24) |
| 5 | 아껴 쓰기 (13) | 두 줄 산맥 ★ (13) | 아래로 가는 분기기 ★ (15) | 다리 두 번 ★ (19) |
| 6 | 첫 손님 (17) | 강 건너 산 넘어 ★ (15) | 대륙 횡단 (16) | 교차로 배달 ★ (31) |
| 7 | 숲속 정류장 (12) | 건너갔다 돌아오기 ★ (17) | 엇갈린 귀환 (24) | 엇갈린 집 ★ (31) |
| 8 | 두 손님 (24) | 두 갈래 터널 (18) | 고리 모양 길 ★ (24) | 배달하고 태우고 ★ (41) |
| 9 | 되돌아오기 (21) | 강 밑 지름길 (20) | 양쪽 손님 ★ (28) | 두 집 배달 ★ (42) |
| 10 | 마지막 운행 (20) | 숨은 지름길 ★ (21) | 8자 노선 (39) | 마지막 배달 ★ (43) |

★는 v0.6에서 새로 만든 판, 괄호는 난이도 점수입니다. 챕터 2~4는 점수가 올라가는 순서로 놓고,
새 규칙을 처음 배우는 판(예: 3-3 선로 전환기)에서만 한 번 쉬워집니다. 각 챕터의 마지막 판이 그 챕터에서
가장 어렵고, 마지막 배달(4-10)이 게임 전체에서 가장 어렵습니다(손님 셋, 터널, 교차 레일, ★★★ 정답 하나).

### 난이도 점수

`npm run difficulty`는 판마다 ★★★ 정답을 놓는 순서대로 한 칸씩 따라가며, 그 칸에 놓을 수 있어 보이는
다른 레일(기차가 빈 땅으로 계속 달리게 되는 것)을 하나씩 시험합니다. 솔버로 끝까지 풀어 봐서 절대 이길 수 없는
것이 **함정**, 다른 길로 이길 수 있는 것이 **갈림**입니다.
점수 = 함정 수 + log2(정해진 레일로 모든 정답을 찾는 데 든 솔버 탐색량).
대략 2는 바로 보이는 판, 10~15는 쉬움, 20은 챕터 1 마지막 수준, 30 이상은 어려움, 40 이상은 보스입니다.

**배포 전 확인:** 스테이지를 추가하거나 고치면 `npm test`(정답·par·경로 수 고정)와 함께
`npm run difficulty`를 돌려 챕터 안 순서와 보스 판이 맞는지 확인하고 나서 `main`에 올립니다.

### 기믹 규칙

- **터널:** 같은 글자의 두 입구가 연결됩니다. 입구가 열린 쪽으로만 들어갈 수 있습니다.
- **교차 레일:** 직선 두 개가 엇갈린 조각입니다. 기차는 언제나 곧게 지나가므로, 한 칸을 가로·세로로 한 번씩 두 번 지날 수 있습니다.
- **분기기:** 고정 배치입니다. 줄기 쪽에서 들어오면 지금 가리키는 갈래로 나간 뒤 방향이 바뀝니다. 갈래 쪽에서 들어오면 항상 줄기로 나갑니다. 등의 화살표가 현재 방향을 보여 줍니다.
- **손님 배달(챕터 4):** 손님마다 색이 있고, 같은 색 지붕 집이 목적지입니다. 손님 칸을 먼저 지나 태운 뒤
  집 칸을 지나면 내립니다(집을 먼저 지나면 아무 일도 없음). 모든 손님을 내려 줘야 도착역에서 성공입니다.
  기차는 손님이 타고 내릴 때마다 잠깐 멈춥니다.
- 같은 위치·방향·분기기 상태가 반복되면 무한 루프로 판정해 실패합니다.

## 구조

```
src/
  engine/            순수 TypeScript 게임 엔진 (React/DOM 의존 없음)
    dir.ts           방향(N/E/S/W)과 좌표 보조 함수
    rail.ts          레일 종류, 회전, 포트(연결 변) 표
    stage.ts         스테이지 형식(ASCII 맵) 파싱과 검증
    step.ts          이동 규칙 한 곳(enter): simulate와 솔버가 공유
    simulate.ts      기차 주행 계산: 경로 trace와 실패 원인/위치, 무한 루프 감지
    editor.ts        배치·회전·삭제·undo·초기화, 자동 방향 맞춤, 드래그 배치(paintStroke)
    generate.ts      오늘의 퍼즐 생성기(시드 난수 + 솔버 검증), 연속 기록
    solver.ts        DFS 솔버: 처음 지날 때 레일을 깔고 다시 지날 땐 따라감. 해의 개수, 최소 레일 수(par)
    geometry.ts      궤도 기하. 레일 그림과 기차 이동이 같은 중심선을 공유
  stages/stages.ts   기차 월드 스테이지 40개를 챕터 4개로 묶음 (ASCII 맵 + 정답)
  penguin/           펭귄 얼음 나라: 규칙·솔버·난이도·스테이지·화면
  daily/             오늘의 퍼즐 로더: Web Worker 생성 + 하루 캐시
  ui/                React 화면과 SVG 아트
    art/             팔레트, 레일, 지형, 역, 기차 SVG 컴포넌트
    Board.tsx        게임판 렌더링과 입력
```

### 핵심 설계

- **결과를 먼저 계산하고 재생:** `simulate()`가 기차 경로 전체와 실패 원인·위치를 계산하고,
  UI는 그 trace를 애니메이션으로 보여 주기만 합니다.
- **같은 기하 공유:** `geometry.ts`의 선분과 원호가 레일 SVG와 기차 위치 계산에 모두 쓰입니다.
  그래서 기차가 곡선에서도 레일 중심을 정확히 따라갑니다.
- **같은 규칙 공유:** `step.ts`의 `enter()` 하나가 이동 규칙을 정의하고, 주행 계산과 솔버가 모두 이를 씁니다.
- **루프 감지:** 분기기는 상태가 바뀌므로 (칸, 방향, 모든 분기기 상태)가 반복되면 무한 루프로 판정합니다.
- **스테이지 난이도 고정:** `stages.test.ts`가 스테이지마다 솔버의 해 개수를 고정해 둡니다.
  스테이지를 고쳐서 지름길이 생기면 테스트가 실패합니다.

## 스테이지 만들기

`src/stages/stages.ts`에 `StageDef`를 추가합니다. 맵 기호:

```
.  빈칸          P  승객(경유지)    S  출발역    G  도착역
T  나무   R  바위   M  산   W  물   H  집
│ ─ └ ┌ ┐ ┘   고정 레일
a b c …       터널 입구 (같은 글자 두 개가 한 쌍)
┼             고정 교차 레일
1 2 3 …       분기기 (switches 설정 필요)
A B C         배달 손님 타는 곳    X Y Z  각각 A B C 손님의 집(내리는 곳)
```

분기기는 `switches: { '1': { trunk: 'W', turn: 'N', initial: 'turn' } }`처럼 줄기 방향, 꺾이는 갈래 방향,
시작 방향(기본 straight)을 적습니다. 플레이어용 교차 레일 수는 `inventory.cross`(기본 0)입니다.

터널은 `tunnels: { a: ['E', 'W'] }`처럼 읽는 순서(위→아래, 왼→오)로 첫 번째·두 번째 입구가
열린 방향을 적습니다.

`║ ═`는 강 위의 고정 다리입니다. `solution`에는 같은 크기의 격자에 **최단** 정답 레일을 적고(레일 수가 par가 됨),
`stages.test.ts`의 `EXPECTED`에 ★★★ 경로 수와 전체 경로 수를 기록합니다.

새 스테이지 설계 순서:

1. 초안 맵을 `StageDef` 배열로 export하는 파일을 만듭니다(인벤토리와 solution은 임시값).
2. `npx vite-node scripts/autotune.ts 초안.ts`: 넉넉한 레일로 모든 정답 경로를 센 뒤, 최단 경로 하나의
   조각 수 근처에서 ★★★ 경로 1~3개, ★★/★ 경로가 생기는 수량을 골라 `solution`과 테스트 기대값까지 출력합니다.
3. 장애물 배치를 자동으로 찾으려면 맵에 `?`(무작위 장애물 후보)를 쓰고
   `npx vite-node scripts/stage-search.ts 초안.ts`를 실행합니다. 여러 번 장애물을 흩뿌려 보고
   별점이 의미 있고 경로가 깔끔한 맵을 점수순으로 보여 줍니다(`par: [최소, 최대]`, `density`,
   `mustUse: 'cross'` 같은 조건을 초안에 적을 수 있음).
4. 고른 맵을 `stages.ts`의 챕터 배열에 넣고 `stages.test.ts`의 `EXPECTED`를 기록합니다.
