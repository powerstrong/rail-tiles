## 우선순위 1 — 앱·코스·저장·배포

- **등록과 진입:** 15개 정거장 + 들꽃 내부 장치 노선 1개, 총 500판·최대 1,500별이다. 처음부터 열린 역은 9개, 기존 보스 조건의 역은 6개다. 추가 브라우저 검사에서 전체 16개 코스의 첫 판·마지막 판 **32곳에 모두 진입**했고 page error가 없었다.

- **노선도:** 390×844에서 15개 역의 이름·터치 영역이 겹치지 않고, 처음 열린 역과 잠긴 역 모두 선택 가능하다. 아래쪽 기존 노선까지 스크롤하고 잠금 조건을 확인한다. 장치 노선은 독립 역으로 중복 노출되지 않는다. 기존 보스 저장을 넣으면 모든 기존 역이 열린다. 첫 화면·아래쪽 지도 스크린샷도 확인했다.
- **저장 호환:** 정식 키 `rail-tiles:progress`, 스키마 2, `RT1.` 형식은 유지된다. 옛 토끼·꿀벌·산호·저울·자수 도장 150개를 함께 읽고, 높은 기존 별·보스 해금·꾸미기·이야기·이어하기를 보존한다. 읽기만 할 때 옛 원문을 덮어쓰지 않는다. 오래된 탭의 저장, 다른 탭 기록 흡수, 코드 왕복 검사도 통과했다. 꿀벌 30→31판, 메모리 1→2→3장 이어하기와 기존 `memory:bye`도 검토했다.
- **서비스워커:** 실제 빌드 산출물의 precache와 힌트 Worker 10개 대표 판을 검증했다. 브라우저 검사는 Pages 하위 경로에서 옛 탭·옛 지연 로딩 자산을 유지하다 탭 종료 후 새 버전으로 교체하고 오프라인으로 재실행하는 흐름을 통과했다. 산호 및 꿀벌 힌트의 오프라인 실행도 통과했다. 새 배포 확인 시에는 기존 탭/PWA 창을 모두 닫아야 새 Worker가 활성화되는 기존 정책을 고려해야 한다.
- **설치:** 별도 `/tmp/final-review-ci`에서 잠금 파일로 `npm ci`를 실행해 104개 패키지 설치가 통과했다. 존재하지 않는 로컬 `node_modules` 심볼릭 링크도 npm이 제거하고 정상 설치했다.

## 비차단 사항 — 기록만 남김

1. **README 116~117행:** 꾸미기 설명이 중복되고 최대 별이 960/990으로 남아 있다. 실제 전체 최대는 1,500, 보너스 15판을 뺀 정규 최대는 1,455다. 게임의 집계·해금 오류는 아니다.
2. **`scripts/lab-release-check.ts:14`:** `hint.worker-*.js` 첫 파일을 고른다. 산호 추가로 같은 접두사의 Worker가 둘이 되어 향후 코드/해시 변경 시 잘못된 Worker를 고를 수 있다. 이번 산출물에서는 올바른 lab Worker를 골라 10/10 통과했다. 후속 정리에서는 고유 파일명이나 명시적인 산출물 연결이 낫다.
3. **추적 중인 `node_modules` 심볼릭 링크:** 머신 전용 `/tmp/newworlds-deps/node_modules` 경로가 저장소에 들어 있다. 별도 설치 실험에서 `npm ci`가 정상 교체하므로 현재 Pages 배포 차단은 아니지만, 저장소 정리 대상이다. 이번 리뷰에서는 건드리지 않았다.
4. **번들 크기:** 메인 JS 818.82kB, gzip 250.81kB로 500kB 경고가 남는다. 코드 분할·초기 로딩 성능은 후속 항목이다. 경고 숨기기나 제한 완화는 하지 않았다.
