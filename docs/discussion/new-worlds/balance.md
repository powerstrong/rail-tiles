# 별사탕 저울 정식 편입 (`balance`)

## 삭제 원인과 바꾼 규칙

[02 검토의 저울 절](../fun-triage/02_Codex_검토.md)의 쟁반·왼쪽·오른쪽 3상태가 만드는 불필요한 왕복과, 빈 접시가 0 대 0이어도 실패하는 혼란을 없앴다. `archive/lab-v1`의 모델·카탈로그를 읽고, 정식 편입된 거울 토끼·꿀벌의 월드 등록·저장·별·해금 구조를 따랐다. 게임 구현은 `src/balance/`에 모았다.

- 사탕은 처음부터 항상 자기 저울의 왼쪽 또는 오른쪽 접시에 있다. 누르면 반대편으로 이동한다. 첫 판은 오른쪽에 2·1·1이 있고 무게 2를 한 번 누르면 2 대 2다.
- 모든 판은 불균형에서 시작한다. 숫자 합과 접시 높이·저울대는 같은 React 상태에서 바로 갱신한다. 전환 타이머, 입력 잠금용 애니메이션, 확인 버튼은 없다. 완료 카드와 다음 판 버튼도 즉시 나온다.
- 모든 저울의 양쪽 합이 같으면 성공이다. 사탕의 색과 서로 다른 SVG 실루엣, 숫자, 무게만큼의 점을 함께 제공한다. 고정 추는 별도 자물쇠 모양과 ‘고정’ 글자로 표시한다.
- 되돌리기·Ctrl/Cmd+Z·처음부터·현재 배치 기준 최소 경로 힌트를 제공한다. 힌트는 답을 자동 실행하지 않고 누를 사탕을 표시한다. 짝꿍일 때는 둘 모두 표시한다. 되돌려도 힌트 별 상한은 유지되고, 처음부터 다시 시작하면 해제된다.
- `starsFor`를 그대로 쓴다. 남아 있는 누름 이력 기준 par 이하 ★★★, par+2 이하 ★★, 그 외 ★. 힌트 사용 시 최대 ★★. 시간제한·실패제한은 없다.

## 장별 설계

| 장 | 새 요소와 발견 | 계산 부담과 진입 |
|---|---|---|
| 1장 · 톡! 나누는 별사탕 | 누른 사탕이 반대편으로 이동한다. 큰 사탕 하나와 작은 사탕 여러 개가 같은 무게가 될 수 있다. 무거운 쪽에서 빼기만 하는 대신 양쪽에서 주고받는 판도 있다. | 첫 판 1회, 두 번째도 1회. 세 번째는 1+2를 모아 3으로 나눈다. 사탕 3→7개, 무게 1~5, 완료 합 최대 12. |
| 2장 · 가만히 있는 황금 추 | **고정 추**. 접시에 남아 있는 추를 포함해서 사탕을 나눠야 한다. 앞 장에서 세던 단위는 유지하며 ‘움직일 수 있는 무게’와 ‘남겨 둘 무게’를 구분한다. | 첫 판은 작은 사탕 한 번으로 새 요소를 체험한다. 추 1~5, 사탕 4→8개. 1~4회, 완료 합 최대 16. |
| 3장 · 함께 움직이는 짝꿍 저울 | **두 저울에 걸친 짝꿍 연결**. ○ 또는 ◇ 표식의 둘은 한 번에 반대편으로 간다. 한 저울을 맞추면서 다른 저울에 생기는 변화를 함께 살핀다. 단순한 독립 저울 두 판이 아니다. | 첫 판은 ○ 한 쌍을 한 번 눌러 두 저울이 함께 완성된다. 처음 두 판은 한 쌍, 이후 두 쌍. 각 저울 3→5개, 무게 최대 6. 1~5회. 모든 정답에 짝꿍 이동이 필요하다. |

장 첫 판은 모두 par 1로 쉬어 간다. 장 보스의 par는 3→4→5다. 큰 합계만 계속 키우는 대신 고정 추, 연결된 두 저울의 영향을 새 판단으로 넣었다. 판 안의 합계와 기울기를 보고 실험할 수 있으며, 오답을 실패로 취급하거나 입력을 막지 않는다.

## 솔버·판 생성·복구 성질

`model.ts`의 동일한 `move()`가 UI와 BFS 솔버에 쓰인다. 이동 단위는 사탕 한 개 또는 짝꿍 한 쌍이다. 모든 이동은 한 번 더 누르면 원상복구되므로 시작점에서 도달한 모든 배치는 시작점과 같은 연결 성분에 있다. 시작점의 실제 정답 경로를 검증했으므로 되돌릴 수 없는 막다른 상태가 없다. 별도 막힘 경고나 복구 버튼을 만들 필요가 없으며, 일반 되돌리기는 언제든 가능하다.

`balance.test.ts`는 이 설명에만 의존하지 않고, 30판의 **총 2,352개 도달 배치(판당 최대 256개)**를 전부 검사한다. 이동 함수를 쓰지 않는 비트 조합 열거와 독립 합산으로 정답 집합을 구하고, 모든 배치에서 정답까지의 최소 비트 차이와 BFS 결과를 대조한다. 모든 이동의 가역성, 상태 범위, 해답 재생, 시작 불균형, par, 장별 장치, 불필요한 왕복을 통한 세 별 등급도 검증한다. 작은 상태 공간이라 힌트는 Worker 없이 즉시 계산하며 미확인 상태나 잘못된 불가능 판정을 도입하지 않는다.

생성: `npx vite-node scripts/balance-generate.ts`. seed는 `5930151` (`0x5a7ca7`), 산출물은 `src/balance/stages.generated.json`이다. 실행 중 무작위 생성은 없으며, 테스트에서 같은 seed의 전체 JSON을 다시 생성해 대조한다. 첫 세 판은 조작 학습을 위해 직접 정한 구성이다. 3장의 고정 추와 합계 상한, 최소 누름 수, 짝꿍 필수 사용을 생성 시 검사한다.

## 통합과 저장 호환

- 월드 ID `balance`, 판 ID `lab-v1-balance-1`~`lab-v1-balance-30`을 유지한다. 처음 노선도에서 선택 가능하며, 공통 스테이지 목록·순차 해금·별·이어하기·도착 및 작별 이야기를 사용한다. 저장은 기존 스키마 2 그대로다. 진행 중 배치의 영구 저장은 기존 월드와 같이 제공하지 않는다.
- 구 실험실 저울 완료 도장만 추가로 허용해 별 1개로 읽는다. 기존 더 높은 별과 다른 월드 기록은 보존한다. 저장 코드 내보내기/가져오기·다른 탭 병합도 검증한다. 다른 삭제 게임은 다시 등록하거나 도장을 이관하지 않는다.
- 공유 파일의 월드 항목·지도 좌표·엠블럼·이야기는 각각 한 덩어리의 작은 추가다. 나머지 퍼즐 모델·생성·판·화면·그림·스타일·전용 단위 테스트는 모두 자기 디렉터리에 있다. 공통 테스트 기대값에는 새 월드 한 항목을 추가했고, 기존 E2E 정거장 수는 9→10으로 갱신했다.

## 남은 문제와 한계

- 실제 초등학생 관찰은 수행하지 않았다. 특히 3장의 ‘한 번 누르면 다른 저울의 짝도 이동’이 바로 이해되는지, 낮은 숫자로 유지한 후반 판단이 재미있는지 관찰이 필요하다. 솔버 검증을 재미의 증거로 취급하지 않는다.
- 실제 iOS/Android 저사양 기기는 미검증이다. 브라우저 터치·뷰포트 검사는 실기기 검사를 대신하지 않는다.
- 노선도 좌표 `[298,596]`은 통합용 임시 자리다. 다른 병렬 월드와 합칠 때 좌표·정거장 수 기대값을 함께 정리해야 한다.
- 기존 주 번들 500kB 경고는 남는다. 커밋·푸시·배포는 수행하지 않았다.
