## 저장 호환성

정식 키 `rail-tiles:progress`, 스키마 2, `RT1.` 코드 형식과 `src/storage.ts`는 변경하지 않았다. 공통 이관 필터는 토끼·꿀벌·산호·저울·구름의 **옛 1~30판 도장 150개**를 함께 허용한다. 도장은 별 1개로 읽되 기존의 높은 별을 낮추지 않는다. 삭제된 게임, 잘못된 번호·앞자리 0, 옛 범위 밖 꿀벌 31판 도장은 제외한다. 꿀벌 31~50판의 정식 별 저장은 그대로 허용한다.

추가 통합 검사는 다음을 확인했다.

- 읽기만 했을 때 기존 정식 저장과 실험실 원문이 바이트 단위로 그대로 남는다.
- 기존 보스 별, 꾸미기·확인 수, 이야기와 `memory:bye`, 이어하기 위치를 보존한다.
- 전체 16개 코스의 마지막 판을 저장한 뒤 오래된 탭이 다시 저장해도 높은 별을 잃지 않는다.
- 저장 코드 내보내기/읽기와 다른 탭 기록 흡수에서도 전체 별과 꾸미기를 보존한다.
- 기존 꿀벌 30판 완료에서 31판으로, 메모리 기존 장 완료에서 다음 장으로 이어지는 검사를 통과했다. 메모리 엽서·지도도 기존 별을 사용한다.

## 테스트 설정과 안정화

공통 실행 설정은 `vite.config.ts`의 **Vitest worker 1개·테스트당 10초**로 유지했다. 별도 worker 환경 변수 없이 `npm test`가 통과한다. Playwright는 공통 설정의 **worker 2개·기본 180초·단언 10초**를 사용한다. 실제 입력이 많은 메모리·자수 30판 완주 두 시나리오만 기존의 명시적 300초 예외를 유지했다.

브라우저 통합 검증에서 두 가지 실행 경합도 정리했다.

- 자수 확대 직후 크기를 한 번만 읽으면 React 갱신 전에 44px를 읽을 수 있었다. 기대하는 56px가 될 때까지 `expect.poll`로 검증하도록 했다.
- 길 잇기에서 raw CDP 드래그 직후 합성 터치의 `pointerup`은 오지만 다음 `click`이 누락되는 경우를 입력 추적으로 재현했다. 드래그 후 복구는 클릭으로, 일반 터치의 완주·되돌리기는 별도로 연속 검증한다. 게임 코드는 바꾸지 않았다. 일반 터치만 사용한 별도 30회 재현 검사는 실패 0회였고, 보강한 정식 모바일 E2E는 **10회 연속 통과**했다.

새 노선도 E2E는 390×844의 15개 정거장 수, 최초 열림 9개·잠김 6개, 이름과 터치 영역 비겹침, 가로 넘침 없음, 모든 역 선택과 잠금 안내, 자수 키보드 선택·진입, 기존 보스 저장으로 전체 기존 역 해금을 검사한다.
