## 규칙과 선택 근거

모든 유효 칸을 한 번씩 방문하고 벌집에 마지막으로 들어간다. 시간·실패 횟수 제한이 없다. 되돌리기·처음부터·현재 상태에서의 한 걸음 힌트, 힌트 사용 시 최대 ★★를 기존 `starsFor()`로 적용한다.

새 타일은 **화살표 꽃 한 종류**다. 화살표 꽃에는 어느 쪽에서든 들어올 수 있고, **나갈 때만 화살표 방향을 따른다.** 직전 칸을 누르거나 거꾸로 드래그하면 화살표와 관계없이 끝 한 칸을 지운다. 규칙을 반복 방문이나 순간이동으로 확장하지 않았다. 그림만 보고 다음 방향을 알 수 있고, 남겨 둘 출구를 미리 고르는 판단이 기존 한붓 그리기에 자연스럽게 이어지기 때문이다.

기존 꽃은 둥근 다섯 꽃잎, 화살표 꽃은 뾰족한 네 꽃잎과 굵은 화살표를 가진 자체 SVG다. 색뿐 아니라 모양·방향·접근성 이름으로 구별한다. 벌이 올라와 있거나 이미 방문한 칸에도 화살표 배지가 남는다. 색상 구분만 요구하지 않으며 외부 캐릭터·이미지를 사용하지 않았다.

41판의 처음 두 번은 오른쪽 꽃, 아래쪽 꽃이다. 출발 꽃과 다음 꽃의 화살표를 따라 바로 조작하면서 배운다. 출발 아래의 실제 꽃을 누르면 출구 규칙을 바로 설명한다. 별도 안내창이나 입력을 막는 연출을 추가하지 않았다. 기존 1판의 16수 유도 길은 데이터 보존 요구에 따라 그대로다.

난도는 앞 장보다 모든 수치를 높이는 방식으로 정하지 않았다. 4장 진입과 5장 규칙 소개에서 선택 부담을 낮추고 새 발견을 준다. 긴 경로나 많은 오답이 재미를 입증하지 않는다. 실제 아이 관찰 없이 흥미를 확인했다고 주장하지 않는다.

## 상태·막힘 판정과 복구

`src/lab/beeSearch.ts`의 기존 제한 탐색을 확장했다. 기존 판은 숫자 키 `(방문 집합 × 칸 수 + 현재 칸)`을 유지한다. 화살표 판의 키는 **화살표 배치 서명 + 방문 집합 + 현재 칸**이다. 배치는 판 안에서 고정이고 입장 방향과 무관한 출구 규칙이므로 별도의 가변 방향 상태는 없다. 같은 방문 집합·끝 칸에서 방문 순서를 합쳐도 전방 규칙이 같다. 복구용 순서 이력은 따로 유지한다. 36칸의 상위 비트도 기존 정확한 숫자 마스크 처리를 사용한다.

탐색은 화살표 출구를 반영한 `exits`를 따른다. 차수·연결 가지치기는 **무방향 이웃**을 사용한다. 방향이 있는 출구 수를 무방향 차수처럼 세어 올바른 경로를 불가능으로 판정하지 않는다. 가능은 실제 재생 가능한 후속 경로, 불가능은 구조적 증명 또는 모든 합법 후속 분기의 불가능 증명이 있을 때만 반환한다.

UI는 질의당 새 상태 6,000개 / 8ms, 메모 50,000개 제한을 유지한다. 8ms는 32개 상태마다 확인하는 소프트 상한이다. 초과는 `unknown`이며 막힘으로 단정하지 않는다. 복구 이력 검사도 전체가 하나의 작업량·시간 예산을 공유한다. `impossible`이면 같은 렌더에서 경고하고 마지막으로 풀 수 있던 지점 복구를 제공한다. 경고·이동 연출은 입력을 잠그지 않는다. 탭·드래그 되짚기는 새 화살표에서도 동일하다.

## 통합과 기존 데이터 보존

- 새 데이터·SVG·생성기·추가 검증은 `src/lab/bee50/`에 둔다. 기존 `stages.generated.json`을 재작성하지 않는다. 기존 토끼 30판과 꿀벌 1~30판이 담긴 파일의 SHA-256은 `950990d2144087f58b142094feda80766e373107984e4faf127303c92105e6f8`로 작업 전과 같다.
- `stages.ts`에서 새 20판을 덧붙이고, 꿀벌 카탈로그의 장 목록을 5개로 확장한다. 기존 정식 월드 등록이 이 데이터를 사용하므로 `worlds.tsx`, 노선도 좌표·정거장·스토리는 수정할 필요가 없다. 처음부터 선택 가능, 순차 해금·별·이어하기·노선도 별 분모 150이 자동 적용된다.
- 30판 완료 기록에서 이어하면 31판으로 간다. 기존 별·다른 월드 별·스키마 2·저장 키·최고 별 병합은 그대로다. 31~50판은 정식 저장을 사용하며, 구 실험실 도장 이관 범위는 기존 1~30판이다.
- 공통 테스트는 판 수·별 분모 변경과 정확성 검사의 벽시계 분리만 반영했다. 새로운 회귀 검사는 전용 파일에 추가했다. 기존 월드 제품 코드나 저장 코드는 변경하지 않았다.

기본 `npm test` 첫 시도에서는 기존 철도·차고지·우주 테스트의 5초 제한과 기존 꿀벌 정확성 검사의 8ms 판정 기대가 호스트 부하에 걸렸다. 꿀벌 정확성 검사는 작업량 6,000개를 유지하고 벽시계 제한만 분리했다(시간 예산 초과 검사는 별도로 유지). 전체 단위 검사는 테스트 실행에만 작업 수 2개 / 테스트당 30초 옵션을 주어 683개 모두 통과했다. **제품의 시간·작업량 제한은 늘리지 않았다.** 브라우저 첫 준비 시 테스트 코드의 직접 JSON import 문제도 기존 파일 읽기 방식으로 수정했다. 잘못된 방향을 누르는 자동화는 ARIA 비활성 안내가 있어도 실제 터치를 보내도록 명시했다. 수정 후 지정 명령 전체 21개가 통과했다.

## 남은 문제

1. 실제 초등학생의 31/41판 규칙 발견, 6×6 계획 부담, 경고 후 재도전 의사는 관찰하지 못했다. 기존 첫 3판의 16수 유도 길도 이번 보존 범위에 포함한다.

3. 기존 주 JS 청크 500kB 초과 경고는 남는다.
