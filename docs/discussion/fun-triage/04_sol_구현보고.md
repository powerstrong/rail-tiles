## 커밋 상태 — 실행 환경 제한

**구현·검증은 완료했지만, 요청한 단계별 커밋과 이 보고서 커밋은 생성하지 못했습니다.** A 단계 검증 후 `git add … && git commit …`을 실행했으나 다음 오류로 중단됐습니다.

```text
fatal: Unable to create '/home/jslee/rail-tiles/.git/index.lock': Read-only file system
```

마운트 정보를 확인하면 작업 디렉터리는 쓰기 가능하고 `.git`만 읽기 전용입니다. 이 환경에서는 권한 상승도 허용되지 않습니다. 제한을 우회하거나 별도 Git 저장소에 가짜 커밋을 만들지 않았습니다. 저장소 author 설정은 `jslee <jslee@plaif.com>`이며 변경하지 않았습니다. 새 커밋 해시는 없고, `main`과 `archive/lab-v1`은 기준 커밋 그대로입니다. **git push는 실행하지 않았습니다.**

검증 시점의 변경을 A/B/C/DE/F/G 누적 패치로 보관했고, 순서대로 적용할 수 있는 개별 패치와 마지막 검증·보고서 패치를 `/tmp/rail-fun-triage-stages.tar.gz`로 내보냈습니다. 기준 커밋의 깨끗한 파일 복사본에 모든 패치를 순서대로 적용한 뒤 최종 작업 파일과 일치하는지 확인했습니다. `.git` 쓰기가 가능한 환경에서 실제 단계별 커밋을 만드는 작업이 남아 있습니다.

## 구현 판단과 근거

### 펭귄

`explore(stage)`를 진입 시 한 번 생성하고 `toWin`을 조회합니다. 키는 기존 `stateKey()`를 공유하여 모든 펭귄 위치·먹은 물고기·깨진 얼음을 포함합니다. 탐색이 잘렸거나 표가 없으면 미확인이고, 불가능으로 단정하지 않습니다. 첫 판에서 위로 밀었을 때와 불가능 상태에서 추가로 이동한 뒤의 복구를 검증했습니다. 막힘 표시 자체는 이동·선택·되돌리기를 잠그지 않습니다. 기존 미끄러짐 연출 중의 잠금은 유지됩니다.

### 꿀벌

첫 3판은 각각 한 칸 이웃, 꺾기, 가장자리를 돌아가기의 수작업 동선입니다. 기존 ID를 유지하며 모든 도달 상태에서 앞으로 완주할 수 있습니다. 생성 스크립트도 이 세 배치를 보존합니다.

판 진입 시 전체 그래프와 역방향 완주 집합을 만들고, 이동 후에는 키를 조회합니다. 상태는 방문 순서 전체를 포함합니다. 되짚기는 복구 기능으로 분리하여, 막힘 판정과 힌트 탐색은 **현재 길에서 앞으로 이어 완주 가능한가**를 검사합니다. 판정은 가능 / 불가능 증명 / 미확인으로 구분하며 탐색 상한·실패는 미확인입니다. 경고가 나와도 입력은 계속 받습니다.

탭과 드래그는 동일한 `act()` 규칙을 사용합니다. 직전 칸을 가리키면 마지막 한 칸만 지우고, 더 오래된 칸이나 건너뛴 칸은 거부합니다. 드래그 좌표 사이를 자동으로 메우지 않습니다. 이력 기반 복구는 직전 한 수가 아니라 마지막으로 완주 가능했던 위치까지 돌아갑니다. 벌집에는 남은 꽃을 먼저 만나야 한다는 이유와 수를 표시합니다.

`reachability.test.ts`에서 꿀벌 30판의 모든 도달 상태를 독립 DFS와 대조했습니다. 현재 꿀벌 전체 도달 상태는 7,381개, 한 판 최대 1,496개입니다. 입문 3판을 고친 뒤 막다른 상태가 있는 판은 27판이며, 그 상태를 바로 안내·복구합니다. 토끼 30판은 전체 5,397개 상태, 최대 455개이며 막다른 상태가 없습니다. `npx vite-node scripts/lab-audit.ts`로 고정 감사 자료를 갱신할 수 있습니다.

로컬 Node 측정에서 그래프 생성은 토끼 최대 약 2.1ms, 꿀벌 최대 약 5.6ms였습니다. 이는 실제 저사양 휴대폰에서의 응답 시간 보장이 아닙니다.

### 거울 토끼와 정식 편입

2번부터 좌우 두 토끼의 다음 방향을 함께 보여 주며, 각 숲에 이동/벽 앞 대기 미리보기를 표시합니다. 실제 이동 뒤에는 각 토끼가 움직였는지 쉬었는지 동시에 알려 줍니다. 집에 들어간 토끼도 다시 움직인다는 문구와 다음 이동 표시를 유지하고, 규칙 자체는 바꾸지 않았습니다.

두 게임은 첫 노선도에서 바로 선택합니다. 정식 스테이지 목록의 순차 해금·별 저장·이어하기·내보내기를 그대로 사용합니다. 별은 기존 `starsFor()` 기준인 par 이하 ★★★, par+2 이하 ★★, 나머지 완료 ★, 힌트 시 최대 ★★입니다. 꿀벌의 완주 길이는 고정이므로 불필요한 별 조건을 새로 만들지 않았습니다. 이전 실험실 도장은 완료 여부만 알 수 있어 별 1개로 이어 주고, 이미 더 높은 별이 있으면 보존합니다.

### 철도 재시도

기존 `simulate()` 결과의 경로를 그대로 재생합니다. 첫 시도는 기본 속도이고, 재시도/완료한 판에는 빠른 확인을 제공합니다. 운행 중에도 재시도를 빠르게 바꿀 수 있습니다. 논리적인 애니메이션 시계를 6배로 진행시켜 이동·가속·감속·승하차 정지를 함께 줄입니다. 기본 운행과 성공 연출은 유지합니다.

취소하면 예약 프레임과 운행 음향 타이머를 정리하고 기차·장치·승객·화물을 초기 표시로 돌린 뒤, 놓은 레일과 편집 이력을 보존해 즉시 수정합니다. 엔진의 한 번 출발 보너스를 사용하는 경우에는 취소를 새 도전으로 처리합니다. 이번에 남긴 장치 20판에는 이 보너스가 없습니다.

### 장치 노선 20판

버튼/차단기·도개교·급수·회전판 각 4판과 종합/화물 4판입니다. 전체 목록과 선택 이유는 `docs/DEVICE_ROUTES.md`에 있습니다. 화물 수만 늘리는 판, 한 번 출발 반복, 제공 해답에서 이름의 복합 장치를 쓰지 않는 판을 우선 제외했습니다. `t2-busy-crossing`과 `t2-two-colors`는 제외했고, 남긴 `t2-boss-2`의 설명은 실제 레버·다리·손님 조건으로 수정했습니다.

내부 월드 `train2`는 저장 호환을 위해 유지하되 독립 로비 정거장을 제거하고, 들꽃 목록의 기본/장치 선택에 연결했습니다. `t2-boss-1`은 장치 1장 네 번째 판으로 유지하여 차고지·우주 해금을 늦추지 않았습니다. 남긴 판의 ID와 모든 기존 별 값은 유지합니다. 제외된 판의 별도 삭제하지 않습니다.

20판의 성공 경로를 모두 열거했고 탐색 중단이 없었습니다. 모든 최단 경로가 해당 묶음의 장치를 사용하며, `t2-boss-1`은 모든 성공 경로에서 두 색 차단기를 통과해야 합니다. 일부 소개판은 더 긴 장치 우회 성공도 허용합니다. 이를 모든 판에서 장치가 절대 필수라는 주장으로 확대하지 않았습니다. 선별은 편집 판단이며 탐색 깊이를 재미의 증거로 취급하지 않습니다.
