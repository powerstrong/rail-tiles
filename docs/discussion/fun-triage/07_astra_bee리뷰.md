## Blocker

없음. 아래 비차단 사항은 남지만, 요청한 5칸 재설계와 기존 보호 장치·기록·배포 동작을 충족한다. 실제 아동 관찰이나 실기기 성능까지 검증했다는 판정은 아니다.

## 1. 실제 난이도와 아이의 조작

- 1~20판은 5열×5행, 21~30판은 5열×6행이다. 가로 5칸을 유지한다. 첫 3판은 각각 17칸·16수이며, **모든 진행 접두 상태에서 합법적인 전방 이동이 정확히 하나**다. 벌집에 일찍 들어가거나 첫 선택부터 막히는 함정은 없다.
- 4판 이후에는 완주 가능한 선택과 불가능한 선택이 실제로 갈린다. 아래 수치는 구현 보고를 인용한 것에 그치지 않고, 별도의 Python 탐색으로 이전 판과 새 판을 계산해 확인했다. 판단 수는 제공 해답의 접두 경로에서 센 값이다.

| 항목 | 이전 `47665cf` | 새 `cdfb0ae` |
|---|---:|---:|
| 1장 평균 실제 판단 수 | 1.2 | 3.1 |
| 2장 평균 실제 판단 수 | 3.4 | 7.9 |
| 3장 평균 실제 판단 수 | 4.2 | 10.8 |
| 4판의 무작위 전방 진행 완주 확률 | 33.3333% | 7.2917% |
| 30판의 무작위 전방 진행 완주 확률 | 25% | 약 0.0192231% |

무작위 확률은 합법적인 미방문 이웃을 균등 선택하고, 조기 벌집 진입·되짚기·힌트·경고에 따른 재선택은 제외한 모델이다. 표본 추출 대신 모든 후속 분기를 합산했다. 따라서 06의 20,000회 표본 비율과 약간 다른 것은 정상이다. 이 수치는 실제 아이의 성공률을 뜻하지 않는다. **단순히 길만 길어진 변경은 아니다.**

- 막힘 경고는 `impossible`일 때만 표시하고 조작을 잠그지 않는다. 브라우저에서 10판의 잘못된 선택 → 즉시 경고 → 직전 꽃 조작 가능 → 마지막 완주 가능 지점 복구 → 힌트까지 통과했다.
- 탭·드래그로 직전 칸을 한 칸씩 되짚기, 비인접 점프 거부, Ctrl/Cmd+Z, 남은 꽃 수·벌집 잠금 이유가 유지된다. 연속 포인터 입력으로 중간 렌더가 생략된 복구 이력도 단위 테스트가 검사한다.
- 후속 판의 오답 선택은 의도적으로 늘었지만, 이를 숨기거나 복구를 막는 새 규칙은 발견하지 못했다. 입문 3판의 무함정 조건과 기존 안내·복구 장치가 유지되어 배포를 막을 새 혼란은 확인되지 않았다.

## 2. 막힘 판정의 정확성

`BeeSearch`의 불가능 판정은 남은 영역의 연결 단절, 필수 진입·진출 차수 부족, 또는 모든 합법 후속 상태의 불가능 증명에서만 나온다. 차수·연결 검사는 필요조건으로 사용되고, 가능 판정은 실제 완주 경로를 보관한다. 방문 순서는 미래 전방 이동의 조건에 영향을 주지 않으므로 `(현재 칸, 방문 집합)` 병합은 타당하다. 되짚기는 이 전방 완주 탐색에 포함하지 않는다.

추가 독립 검증은 다음과 같다.

- Python 정수 방문 집합과 좌표 맨해튼 인접 관계로, 제품의 차수·연결 가지치기를 쓰지 않고 합법적인 모든 전방 분기를 열거했다. 시작점·벌집·빈 칸은 실제 배포 JSON을 사용했다.
- 새 30판의 도달 가능한 **739,820개 고유 `(현재 칸, 방문 집합)` 상태**를 제품 탐색 결과와 대조했다. **가능 3,711개, 불가능 736,109개, 불일치 0개, 미확인 0개**였다. 반환된 가능 경로는 인접 이동·중복 방문 없음·벌집 마지막 도착·전체 칸 방문도 검사했다. 입문 3판은 각 17개 상태 전부 가능하다.
- 이 대조는 정확성 검사이므로 질의의 벽시계 제한을 해제하고 작업량 6,000개를 유지했다. 메모가 40,000개에 도달하면 비워 메모 상한으로 대조가 중단되지 않게 했다. **실제 UI의 8ms 제한에서 모든 상태가 즉시 판정된다고 주장하지 않는다.** 기존 보고의 방문 순서별 상태 수와도 직접 비교하면 안 된다.
- 작업량·시간·메모리 제한은 `unknown`으로 돌아온다. 미확인 자식이 있는 부모를 불가능으로 메모하지 않으며, 확정된 하위 증명만 남긴다. 단위 테스트의 0/1 작업량, 0ms, 50,000개 메모 상한 및 이후 재질의 검사를 통과했다. Worker도 미확인을 불가능 메시지로 바꾸지 않는다.
- 6×6은 36비트 숫자 마스크를 사용한다. 31번 이상 비트는 나눗셈으로 검사하여 JS 32비트 변환을 피한다. 키의 최댓값 `36 × (2^36 − 1) + 35`는 `2^53`보다 작아 정수 충돌이 없다. 서로 다른 방문 순서의 병합, 상위 비트를 포함한 키 구분, 31~35번 칸을 지나는 실제 경로 증명 테스트를 통과했다.

## 3. 성능과 휴대폰

`scripts/bee-benchmark.ts`를 다시 실행했다. 판마다 빈 메모로 20회 진입하고 해답 접두 상태의 합법적 대안을 질의했다. 환경별 진입 600회·이동 19,800회이며 Node v26.13.0, headless Chromium 390×844/CDP CPU 4배 감속에서 측정했다.

| 환경 | 진입 최대 | 이동 질의 최대 | 판별 이동 p95의 최댓값 | 미확인 진입/이동 |
|---|---:|---:|---:|---:|
| Node | 3.19ms | 0.57ms | 0.046ms | 0 / 0 |
| Chromium CPU 4배 감속 | 3.80ms | 3.40ms | 0.100ms | 0 / 0 |

측정 경로에서 질의당 새 상태 최대 132개, 판당 메모 최대 236개였다. 전체 그래프를 판 진입 시 만들지 않으며, 복구 이력은 하나의 6,000상태/8ms 예산을 공유한다. 시간 검사는 32개 새 상태마다 수행하므로 8ms는 소프트 상한이다. 측정은 엔진 준비 후 탐색 호출이며 React 렌더·네트워크·실제 저사양 기기를 포함하지 않는다.

별도의 모바일 브라우저 조작·스크린샷 확인 결과, 첫 판과 마지막 판의 칸은 **320px 폭에서 약 49.59px, 390px 폭에서 약 63.59px**로 모두 44px 이상이었다. 가로 넘침은 0px이며 벌집 잠금 문구가 칸 안에 들어간다. 기존 E2E의 844px 가로 화면도 통과했다. 첫·마지막 판 터치 완주가 가능하다.

## 5. 빌드·서비스워커·배포

- TypeScript와 Vite 프로덕션 빌드 통과. 주 JS는 약 640.44kB / gzip 201.16kB이며 기존 500kB 경고는 남는다.
- 실제 생성된 힌트 Worker로 토끼·꿀벌 1/15/30판 **6/6** 완주 경로와 잘못된 요청 처리를 검증했다. 주 JS·CSS·Worker가 실제 산출물과 오프라인 precache에 모두 있다.
- 서비스워커는 열린 이전 탭을 유지한 채 업데이트를 대기한다. 기존 탭의 지연 자산을 오프라인에서도 보존하고 마지막 탭 종료 후 새 버전을 활성화하는 E2E를 통과했다. `/rail-tiles/` 하위 경로, 새 버전 첫 오프라인 실행, 이전 저장 기록도 포함한다.
- 두 월드 오프라인 재로드·힌트 Worker, 펭귄 복구, 철도 운행 취소·빠른 확인, 장치 노선 및 해금, 완료 화면 포커스 회귀도 통과했다. 배포 워크플로는 이번 커밋에서 변경되지 않았고 테스트·빌드·산출물 검사·브라우저 검사를 배포 전 실행한다.

## 비차단 사항

1. **실제 아이의 난이도 체감은 미검증.** 입문 3판 뒤 4판부터 선택 부담이 크게 늘고, 후반은 무작위 진행으로 거의 완주하지 못한다. 요청한 난도 상승은 확인했지만 16수 입문 길의 지루함, 후반 계획 부담, 경고·복구를 이용한 재도전 의사는 아동 관찰이 필요하다. 이를 이유로 검증된 판을 임의로 다시 쉽게 바꾸지는 않았다.
2. **후반판의 도움 도구는 세로 스크롤이 필요하다.** 390×844에서 30판 보드는 약 y=686까지 보여 전체 보드는 들어오지만 도움 도구 하단은 약 y=921이다. 320×844에서는 도구 하단이 약 y=873이다. 스크롤·터치 사용은 정상이며 칸 크기를 줄일 사유로 보지 않았다. 향후 위쪽 여백이나 도움 도구 배치를 검토할 수 있다.
3. **정확성 테스트가 실제 8ms 벽시계에 민감하다.** 처음 단위 테스트와 빌드들을 동시에 실행했을 때 새 `reachability.test.ts:37`의 기대값 `possible`이 `unknown`으로 나왔고, 기존 차고지 1개·우주 2개 테스트도 5초 timeout이 났다. 빌드를 겹치지 않은 `npm test` 재실행은 전부 통과했다. 미확인 자체는 제품 계약에 맞는 결과이므로 판정 오류는 아니다. 후속 정리에서는 증명 정확성 테스트와 실시간 예산 테스트를 분리해 CI 부하에 따른 거짓 실패를 줄이는 것이 좋다. 이 리뷰에서 테스트를 느슨하게 바꾸지는 않았다.
4. **기존 번들 크기 경고와 실기기 확인 과제는 유지.** 현재 감속 Chromium 결과를 모든 Android/iOS의 첫 진입·연속 드래그 체감 보장으로 확대하지 않는다.
