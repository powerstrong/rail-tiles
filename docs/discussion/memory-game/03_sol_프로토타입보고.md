# 03 메모리 게임 프로토타입 구현 보고

기준: `01_Claude_초안.md`, `02_Codex_검토.md`의 **프로토타입 확정 사양**.

**짝꿍 보관소(`memory`)를 처음부터 선택 가능한 정식 월드로 추가했다. 1장 ‘첫 짝꿍’ 10판만 구현했고, 기존 별·순차 해금·이어하기·저장 경로로 연결했다.** 커밋과 push는 하지 않았으며 변경은 작업 트리에 남겼다. 기존 두 설계 문서는 수정하지 않았다.

## 구현 판단

- 메모리 상태는 `src/memory/` 안에서 처리한다. `src/lab/PuzzleScreen.tsx`, 공통 `starsFor`, 저장 스키마와 기존 월드 해금 조건은 변경하지 않았다.
- 짝 수는 `2, 2, 3, 3, 3, 4, 4, 4, 6, 6`이고 보드는 행×열 기준 2×2, 2×3, 2×4, 3×4다. 모든 그림은 정확히 두 장이다.
- 불일치 중 다른 뒷면 카드를 누르면 이전 두 장을 덮고 같은 reducer 이벤트에서 새 첫 장을 연다. 공개·성공 카드를 다시 누르면 실수나 대기 상태가 변하지 않는다. 애니메이션 종료를 진행 조건으로 사용하지 않는다.
- 불일치 타이머는 900ms이며 `roundId + attemptId`가 일치할 때만 상태를 바꾼다. 재시작·새 비교·화면 이탈 때 정리하고, 이미 도착한 옛 이벤트도 무시한다. ‘다음 카드를 누를 때 덮기’는 자동 타이머만 끄고 채점에는 영향을 주지 않는다.
- 힌트는 실제 본 미완성 짝만 600ms 테두리로 알려 준다. 첫 장이 있으면 그 상대만 표시한다. 알려 줄 짝이 없으면 비용이 없으며, 불일치 대기도 유지한다. 유효한 도움을 보여 준 경우에만 최대 두 별이 된다.
- 세 별 상한 `ceil(1.5N)`, 두 별 상한 `3N`은 화면 표시와 채점이 같은 함수의 수치를 사용한다. 그보다 실수가 많아도 완료하면 한 별이고 다음 판이 열린다.
- 마지막 짝을 맞추는 렌더에서 보드 아래 결과와 다음 버튼을 바로 보여 준다. 라운드 토큰으로 완료 기록을 한 번만 보내고 제목에 초점을 옮긴다. 카드 위에 결과 버튼을 겹치지 않는다.
- 앞면 그림은 실루엣과 색이 다른 자체 제작 SVG 12종이다. 짝 복사본은 같은 컴포넌트를 사용한다. 성공은 체크·테두리로도 표시한다. 숨은 앞면 SVG는 DOM에 렌더하지 않으며 버튼 이름은 ‘1행 2열, 뒷면’, 공개 후 그림 이름, 성공 후 ‘짝 찾음’을 제공한다.
- 소리는 기존 `src/ui/sound.ts`의 `place`, `pickup`, `arrive`와 음소거 저장을 사용한다. reduced-motion에서는 장식 애니메이션을 제거하고, 900ms 관찰 시간은 유지한다.
- 최초 진입·재입장·‘새로 섞어 시작’마다 seed를 발급한다. reducer와 일반 재렌더는 난수를 소비하지 않는다. 최고 별은 기존 저장에 남으며 판 중간 배치·선택·실수는 저장하지 않는다. 재입장 시 새 카드로 시작한다는 안내를 규칙에 적었다.
- 지도 좌표 변경은 시각적 배치다. 기존 월드 ID·스테이지 ID·해금 관계를 유지했고 정거장 간 거리 검사와 390px 실제 화면 확인을 수행했다.
- 2·3장, 일일 퍼즐, 되돌리기, 시간·실수 제한, 전체 그림·엽서 수집은 추가하지 않았다.

새 브라우저 테스트 2개의 범위:

1. 최초 노선도에서 입장·이야기 건너뛰기·10판 확인, 실제 일곱 번 불일치 후 **한 별 완료와 다음 판 해금**, 10판 전부 버튼으로 완료·별 저장, 완료 제목 초점·다음 버튼과 마지막 판 처리. 스크린샷은 1-9의 동일 배치에서 촬영한다.
2. 일반 모션 환경에서 같은 작업의 빠른 세 클릭 수락, 이전 시도 타이머가 새 첫 장을 덮지 않음, 120ms 효과 중 재시작과 이전 라운드 타이머 무효화, 키보드 Enter, reduced-motion에서도 899ms까지 관찰 후 900ms에 자동 덮기, 수동 관찰 옵션, 본 짝만 알려 주는 힌트와 표시 제거, 320px 가로 넘침 없음, 재입장·새로고침 이어하기 초기화와 기존 별 보존.

브라우저 테스트는 라운드 생성에만 테스트 seed 42를 주입한다. 배치는 카드 공개 후 접근성 이름으로 관찰하며 앱에 숨은 그림을 노출하는 테스트 API를 추가하지 않았다. 스크린샷용 임시 e2e 파일은 만들지 않았다.

검증 중 조정한 사항:

- 처음 전체 단위 테스트는 과도한 병렬 실행에서 기존 기차·우주 솔버 검사 세 건이 기본 5초 제한을 넘었고, 다음 실행은 종료 신호(143)로 끝났다. 제한 시간이나 검증을 줄이지 않고 worker를 2개로 제한한 뒤 전체 672개가 통과했다.
- 전체 브라우저 실행 한 차례는 4174 포트 사용 중 오류로 시작되지 않았다. 이후 재실행은 정상 시작했고 최종 전체 검증도 통과했다. Playwright 서버 설정은 변경하지 않았다.
- 기존 정거장 수 단언만 새 월드 수에 맞게 갱신했다. 기존 저장·해금 검사는 삭제하거나 완화하지 않았다.

## 남은 문제와 확인 한계

- 자동 검증에서 알려진 기능 실패는 없다. 실제 아동의 반복 의사, 4→6쌍 난도 변화와 그림 식별성 관찰은 아직 수행하지 않았다.
- 접근성 이름·키보드·숨은 정보 비노출은 검사했지만 실제 스크린리더와 실기기 터치·효과음 청취는 별도 확인이 필요하다. 브라우저 자동 검증은 Chromium 기준이다.
- 빌드에 약 651KB 메인 JS 청크 경고가 남는다. 이번 범위에서는 전체 앱 분할 구조를 변경하지 않았다. Node의 localStorage 실험 경고와 브라우저 실행의 색상 환경변수 경고도 있었으나 최종 검사 실패는 없다.
- 이어하기는 기존 체계대로 마지막 스테이지를 여는 기능이다. 판 중간 카드 상태를 복원하지 않는 것은 확정 사양이며 규칙에 안내했다.
