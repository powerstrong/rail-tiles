# 05 미지의 세계 — 30판 구현 보고

기준은 [04 Astra 설계의 구현 확정 사양](04_astra_2-3장설계.md)이며, 01~03의 배경과 작업 트리에 있던 1장 10판을 바탕으로 확장했다. 표시 이름은 **미지의 세계**, 저장과 월드 식별자는 계속 `memory`다. 총 3장×10판, 최대 별 90개, 엽서 20장이다. 커밋·푸시는 하지 않았다.

## 구현 판단

- 첫 10판의 ID·제목·행열·그림 세트와 별 기준을 보존했다. 2장 짝 수는 `6,6,6,8,8,6,8,8,8,8`, 3장은 `8,8,8,8,10,10,8,10,10,10`이다. 10쌍 보드는 화면 방향과 무관하게 4행×5열이다.
- 엽서 공개는 성공한 짝의 수만 사용한다. 같은 판과 같은 성공 수에서는 seed·성공 순서가 달라도 DOM이 같다. 힌트·불일치·카드 좌표·남은 그림 목록은 풍경 컴포넌트에 전달하지 않는다. 첫 성공 전에는 종이 가림막만 보인다.
- 가림막은 2행×3·4·5열이며 위 행 왼쪽부터 순서대로 사라진다. 180ms 투명도 효과는 장식뿐이고, 성공·기록·다음 버튼은 즉시 반영한다. reduced-motion에서는 전환하지 않는다. SVG·가림막은 `aria-hidden`이고 포인터 입력을 받지 않는다. 진행 알림은 기존 상태 줄 하나를 사용한다.
- 2장의 풍경은 역사, 숲 아치, 햇살 공터, 나무집·계단, 두 단 폭포, 돗자리·벤치, 아치 다리, 무지개·물웅덩이, 노을·담장, 숲 사이 바다로 구분했다. 카드 그림을 정답 목록처럼 엽서에 나열하지 않았다.
- 3장의 지도는 `1,2 / 4,3 / 5,6 / 8,7 / 9,10` 배치다. 각 조각은 공통 320×500 좌표계의 하늘·섬 지면·왕복하는 길을 같은 위치에서 잘라 보여 준다. 장소별 큰 구조물은 조각 내부에 두어 경계의 길과 배경이 끊기지 않는다. 마지막 도착 깃발과 표식은 3-10의 오른쪽 아래 마지막 가림막 안에 두어 마지막 짝을 찾을 때 공개된다. 플레이 중에는 현재 한 칸만, 앨범에서는 소장한 칸만 표시한다.
- 엽서 소장은 알려진 20개 ID의 별이 1·2·3인지로만 계산한다. 새 저장 키·스키마·가짜 별 키·부분 엽서 저장을 추가하지 않았다. 한 별과 힌트 완료도 같은 엽서를 받고, 낮은 별 재완료·재시작·이탈로 소장을 잃지 않는다. RT1 코드와 기존 탭 간 병합도 동일한 별 기록을 사용한다.
- 앱은 현재 장의 나머지 아홉 판 완료를 확인해 `clearNote`를 전달한다. 전체 완료는 기존 `allCleared` 계약을 사용한다. 후반 판만 복원한 상태에서는 ‘이번 장소 발견’, 3장만 모두 소장하면 ‘탐험 지도 완성!’, 실제 30판 전체 완료이면 ‘미지의 세계 30판을 모두 해냈어요!’가 된다.
- 기존 `memory:bye` 기록을 삭제하지 않는다. 새 전체 완료 때 자동 작별 재생이 생략돼도 결과와 목록의 작별 인사 다시 보기는 유지한다.
- 기존 900ms 관찰·120ms 카드 공개·300ms 성공 축하·600ms 힌트, 빠른 세 번째 입력 수락과 옛 타이머 무효화, 본 카드만 알려 주는 힌트 규칙을 유지했다. 카드 위치는 성공 뒤에도 움직이지 않는다.
- 6쌍 이상은 보드 여백 10px·간격 8px, 카드 테두리 2px·내부 여백 4px로 고정했다. 큰 글자와 짧은 화면에서는 페이지 세로 스크롤을 허용한다. 완료 결과는 보드 아래에 즉시 생기고 초점과 스크롤이 이동한다.

## 검증

마지막 도착 표식 위치 조정을 포함한 최종 코드로 아래 검사를 완료했다.

| 검사 | 결과 |
| --- | --- |
| `npm test` | **통과: 37개 파일, 684개 테스트** (61.65초) |
| `npm run build` | **통과: TypeScript 검사와 Vite production 빌드** |
| `npm run test:browser` | **통과: 21개 Playwright 테스트**, 최종 실행 2.3분. `MEMGAME_SHOTS=1`로 요청 이미지도 재생성 |
| `git diff --check` | **통과**. 새 파일의 행 끝 공백도 별도로 확인 |

브라우저 검사의 범위:

- 처음 노선도 진입부터 30판을 실제 버튼으로 완주하고, 1장 한 별 완료의 다음 판 해금·장 완료 문구·즉시 결과·제목 초점·30판 저장·마지막 판의 다음 버튼 부재를 확인했다. 전체 완료 후 작별과 20장 앨범·큰 그림도 확인했다.
- 기존 1장 완료 저장이 2-1로, 2-10 한 별 저장이 3-1로 이어지는지 확인했다. 3-9만 있는 저장에서 3-10을 힌트로 완료하면 ‘이번 장소 발견’과 두 칸만 보이며, 빈 지도 칸을 채우거나 전체 완료를 주장하지 않는다.
- 소장한 마지막 판 재입장 때 ‘이미 모은 엽서’와 0/10 공개 상태가 함께 보인다. 열린 앨범은 기존 storage 이벤트를 통해 다른 탭의 별을 반영한다.
- 일반 모션의 빠른 세 클릭, 옛 시도·라운드 타이머, 899/900ms 자동 덮기, 수동 관찰, 유효 힌트·키보드를 유지한다. 엽서의 180ms 전환 중에도 세 번째 카드를 받으며 reduced-motion에서는 전환이 0초다.
- 실제 320×568·390×844·844×390·1280×800에서 6·8·10쌍 카드의 양변이 모두 44px 이상이고 가로 넘침이 없음을 측정했다. 390px에서는 도구 두 버튼까지 화면 안에 들어온다. 앨범도 네 크기에서 확인했고, 320px·200% 글자에서는 제목이 실제 52px로 커지면서 가로 넘침 없이 세로로 이어진다.
- 기존 다른 월드의 완주·해금·기록·입력, 오프라인과 Pages 하위 경로 서비스워커 업그레이드 검사도 함께 실행했다.

검증 중 발견한 문제와 처리:

- worker 2개로 실행한 전체 단위 테스트에서 기존 차고 솔버 1건과 우주 솔버 2건이 5초 제한을 넘었다. 빌드·브라우저와 병행한 실행뿐 아니라 단독 실행에서도 재현돼 worker를 1개로 줄였다. 단일 worker에서도 우주 전체 그래프 힌트 검사가 약 5.6초 걸려 기본 제한을 10초로 조정했다. 테스트 로직·단언·검사 대상·코스는 바꾸지 않았다.
- 추가 복원 e2e의 최초 선택자가 ‘이어하기’만 찾았다. 이미 끝낸 1-10을 복원하면 기존 앱은 ‘다음 퍼즐’로 2-1을 안내하므로 선택자를 두 상태에 맞췄다. 앱의 이어하기 로직은 수정하지 않았다.
- 30판 완주 e2e는 실제 공개한 카드 이름으로 배치를 관찰하고 다시 섞은 뒤 푼다. 숨은 그림을 읽는 앱 테스트 API는 추가하지 않았다. 테스트 seed만 42로 고정하며, 세 배로 늘어난 완주 작업에 한해 e2e 제한을 300초로 두었다.

## 남은 문제와 확인 한계

자동 검사에서 남은 기능 실패는 없다.

- 실제 아동의 반복 의사와 작은 그림 식별성, 스크린리더 낭독, 실기기 터치·효과음 청취는 관찰하지 않았다. 자동 브라우저 검증은 Chromium이다.
- safe-area 여백을 CSS로 반영했지만 실제 노치 기기에서의 확인은 남아 있다.
- 메인 JS 청크의 500KB 경고가 남는다. 전체 앱의 코드 분할 구조는 이번 범위에서 변경하지 않았다. Node localStorage 실험 경고와 브라우저의 색상 환경변수 경고도 발생한다.
- 이어하기는 기존대로 마지막 판을 여는 기능이다. 카드 배치·선택·실수·부분 엽서는 복원하지 않으며 규칙에서 새 카드로 시작한다고 안내한다.
