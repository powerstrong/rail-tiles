# 새로운 세계 실험실

실험실은 정식 월드에 넣기 전에 실제로 놀아 보고 비교하는 독립 공간이다. 타이틀과 노선도에서 들어가며, 10개 게임의 각 30판을 첫 방문부터 모두 선택할 수 있다. 정식 등록은 이 작업에 포함하지 않는다.

## 기존 패턴과 새 방향

기존 8개 월드는 레일 배치, 얼음 미끄러짐, 거울 레이저, 용암 차단, 차량 밀기, 전체 중력 이동, 박자 이동을 중심으로 구성돼 있다. 실험실은 같은 판에 다른 그림만 입히지 않고 조작과 판단을 달리한다.

| 게임 | 핵심 판단 | 진행에서 늘어나는 요소 | 관찰할 점 |
|---|---|---|---|
| 도토리 정원 | 밀기 전 돌아올 공간 확보 | 도토리 1→2→3개, 통로와 순서 | 밀기와 당기기의 차이를 바로 이해하는가 |
| 거울 토끼의 숲 | 한 입력의 서로 다른 결과 | 독립된 두 지도, 벽을 이용한 상대 위치 조절 | 반대 이동 표시와 막힌 토끼의 대기가 명확한가 |
| 반딧불 축제 | 한 조작이 이웃에 미치는 영향 | 3×3→4×4→5×5, 필요한 조작 수 | 시행착오 후 자기만의 패턴을 발견하는가 |
| 무지개 산호초 | 눈앞의 크기보다 다음 색의 연결 | 3→4→5색, 더 넓은 산호초 | 색+모양으로 색 구분에 어려움 없이 플레이하는가 |
| 구름 자수 공방 | 가로·세로 단서를 함께 추론 | 4×4→5×5→6×6, 필요한 추론 라운드 | 연속 묶음 사이 빈칸 규칙을 이해하는가 |
| 별사탕 저울 | 수를 묶고 나누어 합 맞추기 | 카드 3→7개, 오른쪽 고정 추 | 합 표시가 계산을 돕고 답을 대신하지 않는가 |
| 달 토끼의 돌다리 | 마지막 돌을 위해 순서 거꾸로 생각하기 | 한 번의 도약→13번의 도약 | 남겨야 할 별 자리와 사라지는 돌을 구분하는가 |
| 별빛 모자이크 | 빈칸을 순환시키며 공간 확보 | 6조각→9조각, 최단 1→20회 이동 | 완성 그림과 현재 판을 쉽게 비교하는가 |
| 꿀벌의 한붓 꽃길 | 막힐 칸을 미리 보고 전체 경로 계획 | 꽃 수와 실제 갈림길 수 | 벌집을 마지막에 들어가는 규칙이 명확한가 |
| 수달의 연못 다리 | 부분 수량과 전체 연결 함께 만족 | 섬 3→10개, 이중 다리와 교차 제약 | 숫자 충족과 전체 연결의 차이를 이해하는가 |

각 게임은 10판씩 3장이다. 장이 바뀔 때 판의 크기나 새 요소가 늘 수 있으므로 최단 행동 수가 매 판 단조 증가할 필요는 없다. 서로 다른 게임의 행동 수로 난이도를 비교하지 않는다. 저울 배치와 다리 수 설정의 검증 행동은 UI의 탭 횟수와 다를 수 있어 화면에서 최단 클릭 수로 표시하지 않는다.

## 초등학생을 위한 공통 선택

- 시간제한·실패 횟수 제한·스테이지 해금 없이 자신의 속도로 실험한다.
- 되돌리기, 처음부터, 규칙 다시 보기, 한 수 힌트를 제공한다.
- 힌트를 사용해도 완료 표시를 깎지 않는다. 힌트가 자동으로 퍼즐을 끝내지는 않는다.
- 막힌 상태와 탐색 예산 초과를 구분한다. 탐색을 다 하지 못한 것을 "답이 없다"고 표시하지 않는다.
- 힌트 계산은 Web Worker에서 수행하며 이동·되돌리기·스테이지 이동 시 지난 계산을 취소한다.
- 산호에는 색과 함께 서로 다른 모양을 사용한다. 버튼에는 조작과 좌표를 설명하는 접근성 이름을 붙인다.
- 새 단서는 첫 판과 규칙 보기에서 다시 확인할 수 있다. 이야기와 목표는 게임마다 따로 갖는다.

## 기록과 후보 평가

실험 기록 키는 `rail-tiles-lab-v1`이다. 정식 기록 `rail-tiles:progress`의 별, 해금, 꾸미기, 이어하기는 건드리지 않는다. 실험실 완료와 게임별 "또 하고 싶어요 / 다듬으면 좋아요 / 아직 모르겠어요" 평가는 현재 브라우저에 저장된다. 평가는 정식 게임 편입이나 외부 전송을 실행하지 않는다. 기존 정식 기록 내보내기 코드에는 실험 기록이 포함되지 않는다.

실험 판 구조를 크게 수정할 때는 ID 버전을 올려, 다른 문제의 완료 표시가 이전 판에서 넘어오지 않도록 한다. 이번 고정 판은 `lab-v1-종류-번호`를 사용한다.

## 개발과 검증

```bash
npm run dev
npm run lab:generate
npm test
npm run build
```

`lab:generate`는 고정 시드로 판을 만들고 해답을 재생·독립 탐색한 뒤 `src/lab/stages.generated.json`과 `docs/lab-stage-audit.{md,json}`을 갱신한다. 플레이할 때는 생성기를 실행하지 않고 고정 데이터만 읽는다. 상세 측정 결과는 [스테이지 검증](lab-stage-audit.md)을 참조한다.

자동 검증은 해답, 규칙, 경계 조건, 기록 분리를 보장하기 위한 것이다. 초등학생의 읽기 속도나 재미를 실측한 결과는 아니다. 실제 관찰에서 막힌 지점과 반복하고 싶은 게임을 기준으로 정식 후보를 선별한다.

## 화면 점검과 남은 확인

소스 규칙 검사 외에 모든 300판의 초기·완료 보드를 정적 렌더링하고, 각 장 마지막 판의 중간 상태 힌트 표시를 검사한다. 3×3 반딧불의 도달 가능한 512상태와 6조각 모자이크의 360상태는 독립 전수 탐색의 최단 거리와 비교한다.

```bash
npm run lab:release-check
```

이 명령은 프로덕션 빌드 후 실제로 번들된 힌트 Worker에 게임마다 1·15·30번 문제를 보내, 반환된 해답을 엔진으로 재생한다. 지연 로딩 JS·CSS·Worker가 오프라인 캐시 목록에 포함됐는지도 확인한다.

이번 개발 세션은 격리 환경에서 네트워크 소켓 생성이 차단되고, 설치된 Firefox의 headless 실행도 실패했다. 따라서 위 검증을 실제 브라우저 클릭·터치·스크린샷 검증으로 표현하지 않는다. 로컬 브라우저에서 다음을 추가 확인해야 한다.

1. `npm run dev`의 주소를 열어 타이틀과 노선도 두 곳에서 실험실로 들어간다.
2. 게임마다 1번을 완료하고 30번으로 바로 이동한다. 별이나 해금 조건이 붙지 않는지 확인한다.
3. 규칙 접기, 잘못된 선택, 되돌리기, 초기화, 힌트, 이전·다음 판, 완료 후 재도전을 각각 확인한다.
4. 모바일 320·360·390px와 가로 화면에서 자수의 "칸 크게 보기", 토끼의 "숲 크게 보기"를 확인한다. 확대 자수는 판 안에서만 좌우 스크롤돼야 한다.
5. 방향키를 입장 직후와 도움 도구를 누른 뒤에 사용한다. Tab·Enter·Space로 버튼을 이용한다.
6. 새로고침과 다른 탭에서 완료 도장·평가가 보존되는지, 정식 게임의 기록과 이어하기가 유지되는지 확인한다.
7. 프로덕션 미리보기에서 설치·오프라인 재접속으로 실험실의 지연 로딩과 힌트가 동작하는지 확인한다.
